# 新聞搜尋與資料查核看板修正版

此版本移除原程式無依據的百分比與事實保證。原有七類敘述只保存在 `data.json` 的待驗證紀錄中，網頁不公開其文字。沒有新增人物背景、民意調查、工程實績或候選人資格的事實認定。

## 啟動

建議 Python 3.11 或更新版本。在本資料夾開啟終端機：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

需要連網才能安裝套件與取得 Google News RSS。保留 `app.py`、`data.json` 在同一資料夾。原始下載檔未被覆寫。`requirements.txt` 固定本次測試環境使用的直接相依套件版本。

## 初始狀態

- 目標選舉年度為 2026；選區尚未設定，沒有自動沿用舊區劃。搜尋關鍵字只是查詢輸入，不代表人物身分已核實。
- 七類舊版主張標示「待驗證」；SWOT 與策略建議停止展示。
- 團隊資源配置目標與實際工作清冊皆空白，頁面顯示「尚無資料」。
- 新聞搜尋紀錄一律標示「內容尚未獨立查證」。新聞列表與人工主張審核是兩個獨立流程，完成某主張審核不會使所有相關報導自動通過查證。

## 維護資料

以 UTF-8 編輯 `data.json`，保留 `schema_version: 1`。欄位不完整或格式錯誤時，程式會停止呈現資料並提示錯誤，不回填假數字。日期格式使用 `YYYY-MM-DD`，時間包含時區，例如 ISO 8601 的 `+08:00`。實際登錄時應填真實時間，不要複製範例時間。

### 選區 election

維護者應閱讀目標年度正式公告，確認適用屆次／年度後再填：

- `target_year`：目標選舉年度；`applicable_year`：公告實際適用年度，兩者必須相同。
- `status`：完成核對後填 `已人工核對公告`；未完成填 `尚未設定`。
- `district_name`、`areas`：依正式公告填選區名稱與行政區陣列。
- `announcement_title`、`announcement_excerpt`、`announcement_url`、`announced_on`：公告標題、適用區劃的原文摘錄、正式公告連結與發布日期。
- `reviewer`、`reviewed_at`：實際核對者與核對時間。

網址只允許 `cec.gov.tw` 或其子網域的 HTTPS 公告；這是來源限制，不是自動辨識公告年度或判讀內容的工具。公告適用年度與摘錄仍須人工核對。未提供公告前不要填入推測的區劃，也不要把網站首頁當作公告。

### 主張 claims

每筆有 `id`、`category`、`text`、`status`、`evidence`、`reviewer`、`reviewed_at`、`review_note`。

- `待驗證`：頁面只統計筆數，不顯示敘述。
- `已有支持證據`：有可追溯證據並已完成審核登錄；不等於永遠正確。
- `有爭議`：必須附爭議相關證據及審核結論。
- `已更正`：`text` 填更正後內容，`review_note` 說明更正原因；維護紀錄同時保留原狀態、變更理由和參照編號。錯誤舊說法不要維持為現行敘述。

後三種狀態必須有至少一筆證據。每筆 `evidence` 需填：

| 欄位 | 內容 |
|---|---|
| `url` | 可追溯的 HTTPS 證據連結 |
| `publisher` | 發布機關或媒體名稱 |
| `source_type` | 官方公告、原始文件、獨立採訪、當事人聲明等實際類型 |
| `origin_id` | 原始來源編號；同一新聞稿的多次轉載應共用原始來源編號 |
| `excerpt` | 實際支持或反駁該主張的原文摘錄 |
| `published_on` | 證據發布日期；查不到時先維持待驗證 |
| `checked_at` | 人工檢查時間，包含時區 |

人物經歷、工程實績、人口與民意判斷應拆成可逐項查核的主張，不能以一則概括連結同時保證多項主張。當事人自述不應自動提升為獨立證實；政府工程存在也不代表某人促成或民眾關注度高。`origin_id` 協助追蹤轉載，但程式不會自動證明來源獨立性。

### 內部配置 resource_targets

無核定紀錄時保持空陣列。每筆須填：`issue`（議題）、`allocation_percent`（核定資源百分比）、`approver`（核定人）、`approved_on`（核定日期）、`decision_ref`（核定紀錄編號或位置）、`period`（配置期間）。同表使用同一期間，合計須為 100%。畫面固定標示「團隊議題資源配置目標」，不稱民調或民意關注度。

### 工作清冊 progress

無實際清冊時保持空陣列。每個工作群組需填：

- `name`、`period_start`、`period_end`、`updated_at`。
- `maintainer`：清冊維護者；`register_ref`：完整清冊的紀錄位置／編號，用來核對分母是否完整。
- `tasks`：逐件工作陣列；每筆含唯一 `id`、`registered_on`、`status`、`record_ref`。
- `status` 僅接受 `未完成` 或 `已完成`；已完成者另須有 `completed_on` 和 `completion_ref`。

工作須在統計期間內登錄；完成日期不得早於登錄或晚於統計期間與更新時間。頁面直接計算完成件數／登錄總件數，同時顯示期間、更新時間、清冊依據與逐件紀錄；空清冊顯示尚無資料。

紀錄參照可以是內部文件編號，但必須能由授權審核者實際取得。不得填虛構位置。程式能檢查欄位存在，無法證明內部文件存在或清冊完整。公開部署前，請確認畫面中的清冊及證據不含不宜公開的個資。

### 維護紀錄 maintenance

每次人工修改資料後，新增 `at`、`actor`、`action`、`reference`，記錄真實操作者、時間、變更內容與依據。不要以改寫原紀錄取代更正歷史。

此版本為本地 JSON 維護方式，沒有登入身分認證、不可竄改紀錄或多人簽核；SHA-256 僅供核對檔案版本。正式多人維護時，建議改用具身分驗證、版本歷史、審核權限及備份的資料庫。

## 新聞流程與錯誤處理

- 使用 Requests `params` 編碼搜尋關鍵字；重新整理會在讀取前清除此關鍵字及期間對應的快取。
- 成功回應快取最多 30 分鐘，最多 64 組查詢；沒有背景排程，快取到期後仍須頁面重跑才會抓取。
- 連線／讀取逾時、HTTP 失敗、RSS 格式錯誤與成功但無符合結果分開提示。失敗例外不轉成可快取空表。
- 更新失敗時只顯示同一關鍵字及期間的最後成功資料，明確標成舊資料；舊資料僅保存於該瀏覽工作階段，重啟後不保證保留。
- 依可解析日期篩選最近 7／30／90 天並排序；不明日期置後並標示未知，不承諾資料是最新或搜尋完整。
- 使用 GUID／連結去重；不把相同事件的不同報導自動合併，也不把轉載當作獨立查證。
- 保存 RSS 所提供的媒體名稱與來源網站；不把來源首頁或 Google News 轉介網址冒稱原文。
- 不自動擷取任意出版者網頁或解讀其真偽。限制回應大小，拒絕 DTD／實體宣告及非預期 RSS，避免不受限 XML 輸入。
- 可匯出本次搜尋紀錄供後續審核。匯出檔同樣標示尚未獨立查證。

## 來源選用

選區／資格使用目標年度選委會正式公告；工程使用主管機關核定文件、工程紀錄；人口使用官方統計；人物經歷及實績使用可追溯文件。媒體報導需分辨原始採訪、當事人聲明與轉載，同一來源不能因多次刊登就當作多個獨立佐證。

目前保留 Google News 作為單一新聞搜尋入口，另提供官方與查核機構入口。尚未接入多家授權新聞 API、全文比對或自動事實查核服務。人工證據登錄用來強化可追溯性，沒有自動「保證真實」功能。
